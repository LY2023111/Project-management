# 设计文档：项目排期与 WBS 拆解

> 状态：待用户签字确认
> 日期：2026-11-03
> 关联：workbench-app（Node/Express + MySQL）

## 1. 背景与目标

立项后的排期目前只有两个「截止点」：里程碑计划时间和模块计划上线日，缺少执行层的 WBS 拆解。
本设计补齐：**项目 → 阶段 → 任务**三级 WBS、前置任务依赖、模块进度可按 WBS 自动计算、内置 WBS 模板、逾期预警与「我的任务」视角。

## 2. 已确认的决策（问答记录）

| 决策点 | 结论 |
| --- | --- |
| WBS 层级 | 项目 → 阶段 → 任务（三级） |
| 任务与模块关系 | 任务**可选**关联上线模块（不强制，立项/采购类工作可挂项目） |
| 依赖关系 | 任务可选填前置任务；未关联的不参与依赖；有依赖的画连线 + 顺序警告 |
| 自动顺延 | **不自动顺延**，只做黄色警告（前置未完成/后置开始早于前置结束） |
| 模块进度联动 | 每模块可切换「手动 / 按 WBS 自动」；自动 = 任务加权平均（权重=预估工时，缺省 1） |
| WBS 模板 | 内置模板，套用时**按模块上线日倒排**（预留缓冲天数可选，默认 0） |
| 排期视图 | 甘特图页升级（里程碑◆+模块条+阶段分组+任务条+依赖连线）+ 独立「排期计划」列表页 |
| 我的任务 | 新页签：跨项目列出我负责的任务，可快捷更新 |
| 预警 | 逾期红标 + 项目概览「本周到期/逾期」统计 + 周报自动汇总 |
| 任务权限 | 三级：管理员/项目负责人改全部；任务负责人本人只能改自己任务的状态/进度/实际时间 |

### 加列
- `modules.progress_source` varchar(10) DEFAULT 'manual'（'manual' | 'wbs'）

### 现有里程碑表不动
里程碑继续作为项目级节点（已有计划/实际时间），在甘特图与概览中与阶段/任务并列展示。

## 4. 业务规则

### 4.1 依赖（前置任务）
- predecessor_id 必须与任务同属一个项目（服务端校验）
- **禁止成环**：沿 predecessor 链向上追溯不得回到自身（服务端校验，环检测单测覆盖）
- 警告（不阻断）：① 前置任务未完成而后置任务已开始/计划开始早于前置计划结束；② 前置任务逾期。警告在排期页和甘特图上黄标展示

### 4.2 进度自动计算（progress_source='wbs'）
- 模块进度 = round( Σ(权重ᵢ × 进度ᵢ) / Σ权重ᵢ )，权重 = estimate_hours（空则 1）
- 模块无任务（或权重和为 0）时进度显示为 0，页面提示「暂无 WBS 任务」
- 任务增删改、状态/进度变化时立即重算所属模块；切换 progress_source 时重算一次
- 手动模式（'manual'）行为与现状完全一致
- 任务置「已完成」→ progress=100、actual_end 缺省今天；进度改 100 → status 自动「已完成」（反向联动），均可手动修正

### 4.3 WBS 模板（按上线日倒排）
内置两套（常量文件，后续可扩展）：
- **标准上线**（7 任务）：需求确认(2d) → 方案设计(1d) → 开发实现(5d) → 内部联调(2d) → UAT 测试(3d) → 数据迁移(1d) → 上线与培训支持(1d)
- **轻量上线**（4 任务）：需求确认(1d) → 开发(3d) → 测试(1d) → 上线(0.5d→1d)

套用流程：在模块详情点「套用 WBS 模板」→ 选模板 + 填模块上线日（默认取 plan_date）+ 缓冲天数（默认 0）：
- 从上线日往回倒排：最后一个任务 plan_end = 上线日 − 缓冲；按工期自然日依次前推，前任务 plan_end = 后任务 plan_start − 1
- 生成的任务挂在「目标阶段」（用户选已有阶段，默认自动建「实施」阶段），module_id = 该模块
- 已有任务的模块套用时提示「将追加 N 个任务」，不删除现有任务

### 4.4 权限（三级）
- 查看：沿用项目可见性；另加「我的任务」视角——owner_id=我 的任务即使项目不可见也可见（与 issues 的「指派给我」口径一致）
- 编辑：admin 与项目负责人可改所有任务/阶段；任务负责人本人只能改自己任务的 status/progress/actual_start/actual_end/actual_hours/note（不能改计划日期、归属、负责人、依赖）
- 其他人只读

## 5. 页面与交互

### 5.1 新页签「排期计划」（列表维护）
- 选项目 → 阶段卡片纵向排列（可增删改、上下移、标记状态）
- 阶段卡片内任务表：名称 / 模块 / 负责人 / 计划起止 / 工时(预估/实际) / 状态 / 进度 / 前置 / 操作
- 顶部统计条：任务总数、已完成率、逾期数、本周到期数
- 模块详情/卡片入口：「套用 WBS 模板」

### 5.2 甘特图页升级（时间轴总览）
- 行结构：里程碑◆ → 阶段分组头（含阶段时间条）→ 阶段下任务条（完成绿、进行蓝、逾期红、未开始灰）
- 依赖连线：SVG 折线从前置任务条尾连到后置任务条头
- 今天虚线、点击任务条弹编辑框（沿用现有甘特交互模式）

### 5.3 新页签「我的任务」
- 跨项目列出 owner=我 的任务，按 plan_end 升序，逾期红标、7 天内到期高亮
- 行内快捷操作：开始（status=进行中+actual_start=今天）、完成（弹小窗填实际工时/进度）、填进度

### 5.4 项目概览与周报
- 概览加统计卡：逾期任务、本周到期任务、WBS 总体完成率
- 周报增强：风险区汇总「逾期任务」「本周到期任务」；模块进展表新增「WBS 完成度」列（有任务的模块）；下周计划含「计划到期任务」

## 6. 明确不做（范围外）
- 计划基线与变更留痕；自动顺延排程；消息/邮件推送；拖拽调整（点击编辑代替）；资源负载视图；工作日历（按自然日排）

## 7. 实现要点

- 路由：`server/routes/phases.js`、`server/routes/tasks.js`（REST，validate.js 加 rules + FIELD_ALIASES 归一化）
- 进度重算：`server/wbs.js`（纯函数 calcModuleProgress、detectCycle、模板倒排 expandTemplate）便于单测
- 前端：app.js 新增 renderSchedule / renderMyTasks，甘特 renderGantt 扩展；styles.css 补样式
- bootstrap 联表返回 phases/tasks（含 owner_name、module_name、predecessor_name、is_late、blocked_warning）
- TDD：先写 `test/wbs.test.js`（环检测、加权计算、倒排算法）→ 再集成测试（CRUD/权限/联动/模板/周报聚合）→ 最后冒烟

## 8. 验收标准

1. 建项目 → 建阶段 → 建任务（含关联模块、前置依赖、负责人）全链路可用
2. 模块切「按 WBS」后，改任务进度，模块进度与项目进度自动更新
3. 套用模板：按上线日倒排日期正确（含缓冲），任务挂对阶段和模块
4. 成环被拒绝并有可读报错；跨项目前置被拒绝
5. 任务负责人只能改自己任务的限定字段（越权 403）
6. 「我的任务」能看到无项目可见性但负责人是自己的任务
7. 甘特图能看到阶段/任务条与依赖连线；逾期红标正确
8. 周报包含逾期任务与 WBS 完成度
9. 全部测试通过，生产库平滑加列不破坏现有数据（郏县妇幼）
